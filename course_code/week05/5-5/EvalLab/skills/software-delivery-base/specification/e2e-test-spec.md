# E2E测试规范

> 本文件指导测试角色编写端到端（E2E）测试用例。

## 一、E2E测试范围

### 必须覆盖的场景
| 场景类型 | 说明 | 示例 |
|---------|------|------|
| 核心业务流程 | P0/P1需求的主路径 | 用户登录→创建任务→提交→审批 |
| 跨模块交互 | 涉及多个模块协同 | 订单创建→库存扣减→支付→发货 |
| 数据一致性 | 写入后读取验证 | 创建后列表可见、详情正确 |

### 不需要E2E覆盖的场景
| 场景类型 | 原因 | 替代方案 |
|---------|------|---------|
| 单元逻辑 | 复杂度低 | 单元测试 |
| 纯UI样式 | 无业务逻辑 | 视觉回归测试 |
| 第三方服务 | 不可控 | Mock + 集成测试 |

## 二、测试框架选型

### 后端E2E
- 框架：Spring Boot Test + TestContainers / RestAssured
- 数据库：H2内存数据库 / TestContainers MySQL
- 缓存：Embedded Redis

### 前端E2E
- 框架：Playwright / Cypress
- 覆盖页面：核心业务页面（登录、列表、表单、详情）

### 移动端E2E
- 框架：Appium / Detox / Maestro
- 覆盖场景：核心用户旅程

## 三、测试用例编写规范

### 用例结构（AAA模式）
1. **Arrange**：准备测试数据、前置条件
2. **Act**：执行操作步骤
3. **Assert**：验证预期结果

### 命名规范
- 文件：`{Feature}.e2e.{ts|java}`
- 方法：`should_{预期行为}_when_{条件}`
- 示例：`should_return_user_list_when_admin_login`

### 测试数据管理
- 每个测试用例独立数据，测试间不共享状态
- 使用工厂模式或Fixture生成测试数据
- 测试后清理数据（@AfterEach / teardown）

## 四、CI集成
- E2E测试在后端/前端单元测试通过后执行
- 失败时生成截图/录屏
- E2E测试失败不阻塞合并（可配置为warning）
