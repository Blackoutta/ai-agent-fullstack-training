# plans 目录 — 工作包、开发任务计划与开发任务设计（PM + 架构师产出）

本目录存放开发任务相关的文档，供研发角色直接使用：

## 工作包（Work Package）

### 功能开发工作包

命名格式：`WP-<编号>-<简述>.md`

每个工作包是一个可独立交付的最小功能单元，包含：
- **目标**：做什么、为什么做
- **约束**：技术限制、参考代码、业务规则
- **验收标准**：可勾选的验收项

粒度原则：
- 小任务（单接口/单页面）：目标 + 约束 + 验收
- 中等任务（多接口/多页面）：补充接口格式、错误码、表结构
- 大需求（跨模块/跨端）：拆成子工作包

### Bug 修复工作包

命名格式：`WP-<编号>-fix-<bug简述>.md`

Bug 修复工作包专注于问题定位和修复验证，包含：
- **Bug 信息**：Bug 编号、严重程度、影响版本
- **问题描述**：现象、影响范围
- **复现步骤**：详细的操作步骤和复现概率
- **根因分析**：直接原因和根本原因
- **修复方案**：修复策略、修改范围、风险评估
- **验收标准**：修复验证、回归测试、无新问题引入

模板见 `work-package-bugfix-template.md`。

### 功能补全工作包

命名格式：`WP-<编号>-complete-<功能简述>.md`

功能补全工作包专注于缺失功能的补全实现，包含：
- **补全信息**：关联开发任务、负责角色、补全原因
- **缺失功能描述**：功能需求、现有实现分析、影响范围
- **根因分析**：直接原因、根本原因
- **补全方案**：补全策略、实现范围、设计对齐
- **验收标准**：功能已补全、需求对齐、设计对齐

模板见 `work-package-completion-template.md`。

## 开发任务计划（Development Task Plan）

命名格式：`TASK-<编号>.md`

包含：
- 开发任务目标与周期
- 工作包排序（含依赖说明）
- 每个工作包的负责角色
- 风险与阻塞项

## 开发任务设计文档（Development Task Design）— 架构师产出

命名格式：`DES-<开发任务编号>-*.md`

当 `design/` 下已有系统级设计文档时，架构师根据已有设计 + PM 开发任务计划，在此目录生成开发任务级设计文档。**不修改 `design/` 原有文件。**

- `DES-001-核心功能.md`：本次开发任务技术方案概要
- `DES-001-api.md`：本次开发任务涉及的接口设计
- `DES-001-db.md`：本次开发任务涉及的表结构变更
- `DES-001-frontend.md`：本次开发任务涉及的前端页面/组件设计
