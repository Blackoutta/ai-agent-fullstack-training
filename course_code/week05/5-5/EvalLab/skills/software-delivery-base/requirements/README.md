# requirements 目录 — 需求文档（输入）

将需求文档放在本目录。skill 启动后会读取本目录下所有 `.md`/`.txt`/`.docx`(文本) 文档（README 除外）作为需求输入。

## 建议内容

需求文档应至少包含以下内容，便于后续设计与实现：

1. **背景与目标**：解决什么问题、业务价值
2. **功能清单**：编号、功能名称、功能描述、优先级
3. **业务规则**：每条规则要有明确条件与预期行为
4. **数据实体**：涉及的核心业务对象及其属性
5. **页面/交互需求**：需要哪些页面、页面布局、关键交互
6. **非功能性需求**：性能、并发、安全、兼容性等
7. **用例/场景**：典型操作流程与异常场景

## 命名建议

- `REQ-<编号>-<简述>.md`，例如 `REQ-001-用户登录.md`
