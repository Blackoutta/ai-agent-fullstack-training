| 状态 | 含义 |
|------|------|
| ✅ 已覆盖 | 需求→设计→代码→测试全链路完整 |

| ❌ 未覆盖 | 需求未被实现或未测试 |
| 🔄 变更中 | 需求变更后正在同步 |

## 追溯维度说明

1. **需求→工作包**：每个需求至少映射到1个工作包（阶段1补全）
2. **工作包→开发任务**：每个工作包归属到1个TASK（阶段1补全）
3. **需求→设计文档**：每个需求对应的设计文档章节（阶段2/3补全）
4. **设计→代码**：每个设计项的实现位置（阶段3补全）
5. **需求→测试**：每个需求对应的测试用例（阶段6补全）

## 使用说明

1. **阶段1（PM）**：填充需求ID、名称、描述、优先级、WP编号、TASK编号
2. **阶段2/3（架构师）**：填充设计文档列
3. **阶段3（研发）**：填充后端代码、前端代码、移动端代码列
4. **阶段6（测试）**：填充测试用例列，更新覆盖状态
5. **阶段6（测试）**：生成需求覆盖率度量报告

## 质量门禁

| 门禁 | 阈值 | 不达标处理 |
|------|------|-----------|
| 需求→设计覆盖率 | 100% | 回阶段3补全设计文档 |
| 需求→代码覆盖率 | 100% | 回阶段3补全代码实现 |
| 需求→测试覆盖率 | ≥90% | 回阶段6补测，3轮后用户确认 |
