## 回归测试用例选择策略

### 基于变更的回归
1. **直接影响**：变更文件对应的测试用例（必须执行）
2. **间接影响**：依赖模块的测试用例（建议执行）
3. **历史故障**：该模块历史Bug相关用例（建议执行）

### 基于风险的回归
1. **高风险模块**：核心业务模块、资金相关、权限相关
2. **高变更频率**：近期变更频繁的模块
3. **低测试覆盖**：覆盖率低于阈值的模块

## 回归执行流程

```
代码变更 → 影响分析 → 选择回归集 → 执行测试 → 生成报告 → 确认结果
```

### 自动化回归
- 后端：`mvn test` 执行全量单元测试
- 前端：`npm run test` 执行全量单元测试
- E2E：Playwright/Cypress 执行核心流程

### 手动回归
- 探索性测试（新功能交互）
- 兼容性测试（不同浏览器/设备）
- 性能回归（响应时间对比）
