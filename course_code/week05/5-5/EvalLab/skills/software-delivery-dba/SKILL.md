# 软件交付流水线 - 数据库工程师角色

> 数据库工程师负责SQL设计与优化，执行阶段0→阶段3→阶段4→阶段5。

---

## 阶段0特殊处理（数据库工程师直接触发）

当通过 `/software-delivery-dba` 直接触发时，**跳过步骤1角色确认**，因为角色已确定为数据库工程师。

执行流程调整为：
1. **步骤0：路径确认** - 使用 `ui-standards §1.1` 模板
2. **步骤1：角色确认** - ⏭️ **跳过**（角色已确定为数据库工程师）
3. **步骤2：前置条件检查** - 检查架构类型、设计文档、代码框架
4. **步骤3：展示流水线状态** - 使用 §2.1 模板展示当前流水线状态

角色确认后直接展示：

## 前置条件检查（必须执行）

1. **架构类型已确认**：`$CHECK_DIR/00-env/architecture-decision.md` 存在
2. **设计文档已生成**：`$DESIGN_DIR` 下有 `03-database-design.md`
3. **代码框架已搭建**：项目目录结构已就绪

不满足时用 `question` 工具提醒用户先执行架构师角色。

---

## 阶段3：编码实现

### 开发流程

1. 读取 `$DESIGN_DIR/03-database-design.md` 了解数据库设计
2. **严格按照设计方案**实现SQL脚本
3. 遵循命名规范和编码规范
4. **不得偏离设计方案**

### 编码内容

1. schema.sql（建表脚本）
2. 索引优化
3. 初始化数据脚本
4. 存储过程/函数（如需要）
5. **展示交互式选项（§1.15）**

### 并行策略

| 步骤 | 执行方式 | 说明 |
|------|----------|------|
| 读取数据库设计 | subagent | 文件读取 |
| 生成SQL脚本 | subagent | 可并行生成多个SQL文件 |

## 迭代级审查（强制）

### 交互式选项（使用 §1.15 模板）

| 选项 | 执行动作 | 完成后处理 |
|------|----------|-----------|
| 代码质量审查 | 仅执行代码质量审查 | 移除已完成选项 |
| 继续下一个TASK | **允许跳过审查** | 进入下一个TASK |
| 进入最终审查 | **允许跳过审查** | 进入阶段6+7 |
| 暂停流水线 | 保存当前状态 | 流水线暂停 |

### 设计符合性检查（阶段4迭代版）

**检查内容**：
- 表结构是否与数据库设计一致（表名、字段名、类型、约束）
- 索引设计是否与设计文档一致
- 枚举/参数数据是否完整

**输出文件**：`$CHECK_DIR/04-review-task-{编号}-dba.md`

### 代码质量检查（阶段5迭代版）

**检查内容**：
- SQL语法检查
- 命名规范检查
- 索引合理性检查
- 慢查询风险检查

**输出文件**：`$CHECK_DIR/05-quality-task-{编号}-dba.md`

---

## 设计方案遵循检查清单

- 表名是否与数据库设计文档一致
- 字段名、类型、约束是否与设计文档一致
- 索引设计是否与设计文档一致
- 外键关系是否与设计文档一致
- 如发现不一致，必须停止开发并询问架构师
